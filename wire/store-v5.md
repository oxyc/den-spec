# Store v5

The single mmap'd artifact den-atlas serves. Store v5 is store v4 plus the redistributable official
rating observations used to calculate its conservative maturity age. The complete inherited layout is
[store-v4](store-v4.md); every v4 section keeps the same name, type, meaning and byte order.

As with every Den wire format, this released version file is immutable. A later layout change creates a
new version rather than editing this document or its vectors.

## What changed from store-v4

- `format_version` is **5**.
- `minimum_age` remains the required one-byte filtering column from v4.
- Eight required `mat_*` sections form a sparse public-authority observation table for title details.
- A reported official rating can have `mat_age = 0xFF`. It remains displayable but supplies no numeric
  filtering evidence and MUST NOT make `minimum_age` zero.

Only observations from sources whose terms permit redistribution may enter these sections. Private
runtime enhancements such as cached TMDB certifications remain inside the serving deployment and MUST
NOT enter this file, its fixtures, exported caches or diagnostics containing title-level values.

A v5 reader MAY accept v1 through v4. Older stores have no detail observations; v1 through v3 also have
unknown `minimum_age`, as specified by v4. A v1-v4 reader refuses v5 from the header version before it can
silently ignore the detail evidence.

## Header

The 64-byte little-endian header is identical to store v4 except:

| offset | type | field |
|---|---|---|
| 8 | `u32` | `format_version` = 5 — an unknown version MUST be refused |

Magic, endianness check, BLAKE2b-64 content hash, section table, row count, dataset version, alignment and
all structural validation rules are inherited unchanged from store v4.

## Maturity filtering and reported ratings

`R` is the header's `row_count`, `N` is the number of observations, and row `i` refers to `keys[i]`.
`mat_o` is the ordinary values-plus-offsets representation: title row `i` owns observation indexes
`mat_o[i]..mat_o[i + 1]`. The other seven arrays are parallel and MUST all have length `N`.

| name | type | length | meaning |
|---|---|---|---|
| `minimum_age` | `u8` | R | unchanged v4 filter threshold `0..18`; `0xFF` unknown |
| `mat_o` | `u32` | R+1 | observation offsets; starts at 0, is monotonic, ends at N |
| `mat_auth` | `u32` | N | required string id of the official authority |
| `mat_authid` | `u32` | N | required string id of the authority's record/certificate identity |
| `mat_raw` | `u32` | N | required string id of the official reported rating, including factual qualifier codes |
| `mat_assess` | `u32` | N | source assessment-date string id; `u32::MAX` when absent |
| `mat_format` | `u32` | N | source format/cut string id; `u32::MAX` when absent |
| `mat_age` | `u8` | N | normalized independent-viewing threshold `0..18`; `0xFF` when unsafe to normalize |
| `mat_runtime` | `u16` | N | source runtime in minutes; 0 when absent |

`mat_auth`, `mat_authid` and `mat_raw` MUST resolve to non-empty strings. `mat_assess` is deliberately a
string rather than a calendar integer: official bulk sources include ISO dates, year-only values and
spreadsheet serials, and the store preserves the factual source value rather than inventing precision.

For each title, let `ages` be its `mat_age` values excluding `0xFF`:

```text
minimum_age = max(ages)  when ages is non-empty
minimum_age = 0xFF       when ages is empty
```

A writer and reader MUST validate this invariant. It is what permits an unrestricted-admission label
such as Norway's `Tillatt for alle` to be shown without asserting suitability from birth. Filtering reads
only `minimum_age`; it never substitutes a raw rating or an observation age at request time.

The title-details JSON projection is:

```json
{
  "minimumAge": 10,
  "maturityRatings": [
    {
      "authority": "Medietilsynet",
      "authorityId": "no:123",
      "rating": "10 år",
      "normalizedAge": 10,
      "assessed": "1993-03-01",
      "runtimeMinutes": 90,
      "format": "cinema"
    }
  ]
}
```

`normalizedAge`, `assessed`, `runtimeMinutes` and `format` are JSON `null` for their sentinels. The API
does not expose deterministic matching internals. Authority identity remains available so a client can
label the source and, where a separately maintained authority template exists, link to its official row.

## Test vectors

[`vectors/store-v5.json`](../vectors/store-v5.json) and
[`vectors/store-v5.store`](../vectors/store-v5.store) are generated by the real den-dataset writer:

```sh
python3 tools/store-fixture.py \
  --build-store ../den-dataset/pipeline/build_store.py \
  --out-dir vectors
```

The three rows exercise a normalized rating, a display-only official rating whose normalized age is
unknown, and the other media type. The JSON states what a correct reader returns; both writer and readers
must pin `formatVersion: 5`, the bytes and the decoded values.
