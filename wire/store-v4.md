# Store v4

The single mmap'd artifact den-atlas serves. Store v4 is store v3 plus one required, fail-closed numeric
maturity column. The complete inherited layout is [store-v3](store-v3.md); every v3 section keeps the
same name, type, meaning, byte order and required/optional status.

As with every Den wire format, this released version file is immutable. A later layout change creates a
new version rather than editing this document or its vectors.

## What changed from store-v3

- `format_version` is **4**.
- `minimum_age` is a required `u8` array of length `row_count`.
- Values `0..18` are the minimum age at which the title is eligible without a parent or per-title
  override. `0xFF` means unknown. Values `19..254` are invalid and a reader MUST refuse them.
- The value is the highest age among the public-authority observations that den-dataset confidently
  linked to the title. Unknown, unrated, banned, unrecognized, ambiguous and unmatched records produce
  `0xFF`; they MUST NOT produce zero.

The compact store does not carry raw labels, authority identifiers, match evidence, warnings, parent
accompaniment rules or private provider data. Public-source observations and their provenance remain in
the corpus/build artifact. Runtime signals whose licences prohibit redistribution remain inside the
serving deployment and never enter this file or its fixtures.

A v4 reader MAY also accept v1, v2 and v3. For those stores it MUST behave as if every row had
`minimum_age = 0xFF`. A v1/v2/v3 reader refuses v4 from the header version before it can silently ignore
the safety column.

## Header

The 64-byte little-endian header is identical to store v3 except:

| offset | type | field |
|---|---|---|
| 8 | `u32` | `format_version` = 4 — an unknown version MUST be refused |

Magic, endianness check, BLAKE2b-64 content hash, section table, row count, dataset version, alignment and
all structural validation rules are inherited unchanged from store v3.

## Maturity

`R` is the header's `row_count`; row `i` refers to `keys[i]`.

| name | type | length | meaning |
|---|---|---|---|
| `minimum_age` | `u8` | R | exact numeric threshold `0..18`; `0xFF` = unknown |

Eligibility for a policy with integer `maximumAge` is:

```text
known = minimum_age != 0xFF
allowed = known ? minimum_age <= maximumAge : unknownRatings == allow
```

An unrestricted policy may omit the ceiling, but `0xFF` remains unknown; it never becomes an all-ages
classification. Parent presence, owner PINs, temporary unlocks and title overrides are higher-level
profile/session policy and do not modify this title value.

## Test vectors

[`vectors/store-v4.json`](../vectors/store-v4.json) and
[`vectors/store-v4.store`](../vectors/store-v4.store) are generated by the real den-dataset writer:

```sh
python3 tools/store-fixture.py \
  --build-store ../den-dataset/pipeline/build_store.py \
  --out-dir vectors
```

The three rows exercise age 13, unknown (`0xFF`) and age 7. The JSON states what a correct reader returns;
both writer and readers must pin `formatVersion: 4`, the bytes and the decoded values.
